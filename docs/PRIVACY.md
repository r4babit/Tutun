# Tutun — сведения о данных (проект для первого выпуска)

Tutun — VPN-клиент, а не поставщик VPN-серверов. Серверы и подписки предоставляет выбранный пользователем провайдер. У Tutun нет собственного сервера аналитики, рекламы или регистрации пользователей. Провайдер и проверяемые сайты получают обычные сетевые сведения при соединении.

Локально хранятся подписки с ключами доступа, настройки, измерения задержки и статистика трафика по дням. На Android состояние зашифровано AES-GCM ключом Android Keystore, исключено из backup/переноса. На macOS файл app.json имеет права 600, но НЕ зашифрован средствами приложения; защита диска зависит от FileVault и учётной записи. Удаление Android приложения удаляет ключ и локальные профили.

ID устройства, модель, версия ОС и язык Android отправляются провайдеру подписки только после явного разрешения. Выбор меняется в настройках. На Mac переключатель «Отправлять ID устройства» по умолчанию выключен; включённый, он добавляет к запросу подписки по https заголовки X-HWID (случайный ID, созданный Tutun), X-Device-OS, X-Ver-OS, X-Device-Model, X-Device-Locale. По http и при перенаправлении на другой адрес эти заголовки не передаются (проверено тестами).

Внешние адреса, к которым обращается Mac-версия (сверено с кодом 10.11.2026):
- провайдер подписки — при обновлении подписки;
- адрес проверки (по умолчанию www.gstatic.com/generate_204) — через выбранный сервер: служба каждые 10–300 с (настраивается), приложение — при проверке серверов «настоящим запросом»;
- ipwho.is — при подключении и смене сервера два запроса: напрямую (виден настоящий IP) и через сервер, чтобы показать оба адреса и страну;
- speed.cloudflare.com — только по кнопке теста скорости, через проверяемый сервер;
- api.github.com и github.com — проверка обновлений Tutun (частота настраивается, можно выключить) и скачивание выпуска;
- github.com (runetfreedom) или адрес из профиля маршрутов — обновление гео-баз (по умолчанию раз в неделю), через VPN, если он включён.
QR подписки создаётся локально без внешнего сервиса; сама ссылка даёт доступ к подписке и должна храниться как пароль. Резервная копия настроек Mac — открытый JSON с ключами серверов; хранить её так же.

DNS: в режиме «весь трафик» (служба 2.11+) запросы адресов сайтов идут через VPN; напрямую — только адреса VPN-серверов и, при «Сайты страны — напрямую», домены этой страны (к DNS из настройки «DNS напрямую», по умолчанию 77.88.8.8). До 2.11 системный DNS шёл к роутеру мимо туннеля.

Журнал службы Mac (/var/log/tutun.log) читают только администраторы мака. В нём названия серверов, время подключений и ошибки; адреса отдельных соединений пишутся только при уровне журнала «Отладка».

Android использует системное VPN-разрешение, уведомление и foreground service. Mac использует привилегированную службу. Имя Wi-Fi на Mac используется для доверенных сетей и требует разрешения геопозиции. Список приложений Android запрашивается для выбора маршрутизации.

Диагностический CLI scripts/diagnostics.py выводит только версии платформ/приложения/SDK и архитектуру, без логов, конфигов, адресов, серийных номеров и ключей. Это техническая сводка, не полный журнал. Автоматической отправки отчётов нет.

До публикации: указать имя и контакт издателя, опубликованный URL политики, заполнить декларации магазина по фактически выбранному каналу выпуска. Этот проект не заменяет проверку издателем; незавершённые пункты не отмечаются как выполненные.
